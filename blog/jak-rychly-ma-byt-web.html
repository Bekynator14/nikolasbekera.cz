Jak rychlý musí být web? Co ovlivňuje rychlost stránek

Pomalý web stojí zákazníky. Studie Google ukázaly, že při načítání delším než 3 sekundy odejde více než polovina mobilních návštěvníků. Co rychlost webu ovlivňuje a jak to zlepšit?

NBNikolas Bekera
Březen 2026 · 4 min čtení

Rychlost webu není jen technická záležitost — přímo ovlivňuje, kolik zákazníků na vašem webu zůstane a jestli vám napíše nebo zavolá. Navíc Google rychlost webu bere jako jeden z faktorů hodnocení — pomalé weby se zobrazují níže ve výsledcích.

Co nejvíc zpomaluje web?

  • Nekomprimované obrázky Nejčastější příčina pomalého webu. Fotka z telefonu má 3–8 MB — web by měl mít obrázky pod 200 KB. Stačí je správně zkomprimovat při přidání na web.
  • Špatný hosting Levný hosting na přetíženém serveru zpomalí web i přes veškerou optimalizaci. Server musí rychle odpovídat — ideálně do 200 ms (TTFB).
  • Zbytečné pluginy a skripty (WordPress) Každý plugin přidává kód, který se musí stáhnout. WordPress web s 30 pluginy načítá desítky souborů navíc oproti čistě kódovanému webu.
  • Nenačtené nebo blokující fonty Google Fonts a jiné webové fonty se stahují z externího serveru — pokud se stáhnou pozdě, text se zobrazí až po nich a web vypadá pomalý.
  • Video nebo mapy vložené přímo do stránky YouTube embed nebo Google Maps načítají desítky externích souborů. Nahraďte je lazy-loaded variantou, která se načte až po kliknutí.

Jak změřit rychlost svého webu?

Google zdarma nabízí nástroj PageSpeed Insights — stačí zadat adresu webu a dostanete skóre 0–100 pro mobil i desktop. Nad 90 je výborné, 70–90 je dobré, pod 70 je prostor ke zlepšení.

Výsledky rozděluje do čtyř kategorií (Core Web Vitals):

  • LCP — jak rychle se načte největší prvek na stránce (ideálně do 2,5 s)
  • INP — jak rychle web reaguje na kliknutí (ideálně do 200 ms)
  • CLS — jestli se prvky na stránce neposkakují při načítání (ideálně 0)
  • FCP — kdy se začne zobrazovat první obsah (ideálně do 1,8 s)
Tip Testujte vždy mobilní verzi — většina zákazníků hledá na telefonu. Desktop skóre bývá výrazně lepší a neodráží reálný zážitek vašich zákazníků.

Statický web vs. WordPress — jaký vliv má na rychlost?

Statický HTML web (jako tento) je ze své podstaty rychlý — server pošle hotový soubor bez jakéhokoliv zpracování. WordPress musí pro každé načtení spustit PHP, dotázat se databáze a sestavit stránku — to trvá déle.

Dobře optimalizovaný WordPress může být rychlý — ale vyžaduje cache plugin, správný hosting a pravidelnou údržbu. Statický web je rychlý bez jakékoliv optimalizace.

Pro web živnostníka nebo malé firmy, kde se obsah mění zřídka, je statický web jednoznačně rychlejší a levněji udržovatelná volba.
